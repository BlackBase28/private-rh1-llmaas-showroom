== Workshop Concepts to Reuse

The lab used a few repeatable design ideas that can be adapted to real
enterprise workflows:

* Use shared model endpoints for consistent access control, cost management,
and operational visibility.
* Keep tool access scoped. MCP servers should expose only the data and actions
needed for the workflow.
* Separate investigation from remediation. Read-only analysis can be more
permissive than deployment or system-changing operations.
* Require review before accepting generated code, configuration, or automation
changes.
* Keep an audit trail in systems your organization already trusts, such as Git,
AAP job history, OpenShift events, observability tools, and incident channels.

== Suggested Follow-up Exercises

* Add another read-only MCP tool and define the data it is allowed to access.
* Extend the log analysis prompt with a stricter incident report format.
* Add more tests to the portal application before running the remediation flow.
* Replace the sample notification channel with your team's incident response
channel.
* Compare the same remediation workflow using OpenShift GitOps, AAP, or both.
