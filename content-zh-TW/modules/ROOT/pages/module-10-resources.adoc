== 工作坊中可重複運用的設計概念

本實驗使用了幾個可重複使用的設計理念，可適用於實際的企業工作流程：

* 使用共用模型端點，統一存取控制、成本管理和運維能見度。
* 保持工具存取範圍的最小化。MCP 伺服器應只公開工作流程所需的資料和操作。
* 將調查與修復分離。唯讀分析可以比部署或變更系統的操作擁有更寬鬆的權限。
* 在接受生成的程式碼、設定或自動化變更前，要求人工審查。
* 在組織已信任的系統中保留稽核軌跡，例如 Git、AAP 工作歷史、OpenShift 事件、可觀測性工具和事件處理頻道。

== 建議的後續練習

* 新增另一個唯讀 MCP 工具，並定義其允許存取的資料範圍。
* 使用更嚴格的事件報告格式來擴充日誌分析提示。
* 在執行修復流程前，為 portal 應用程式新增更多測試。
* 將範例通知頻道替換為您團隊的事件回應頻道。
* 使用 OpenShift GitOps、AAP 或兩者，比較相同的修復工作流程。
