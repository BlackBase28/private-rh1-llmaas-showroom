= Agentic AI for Enterprise Edge Remediation

== Welcome to the Workshop
This is more than an introduction to AI tools. It is a hands-on enterprise remediation journey across platform operations, application development, and Edge deployment.

Enterprise applications may run across distributed RHEL environments, including manufacturing facilities, financial service locations, retail stores, telecommunications sites, and remote technology infrastructure. These environments require secure, reliable, and auditable processes for troubleshooting and software updates.

In this hands-on workshop, you will rotate between two key personas:

* As a **site reliability engineer (SRE) or DevOps practitioner**, you will prepare Models-as-a-Service, the RHOAI Playground, MCP servers, Grafana, and controlled access to remote RHEL or Edge environments.

* As a **Developer**, you will use a Cline-powered AI Development Agent in OpenShift Dev Spaces to analyze remote application logs, generate remediations, review code changes, and complete a controlled redeployment.

At the end of the workshop, you will understand how RHOAI, MCP, GitHub, Argo CD, Ansible Automation Platform, and RHEL image mode can work together to deliver a controlled, verifiable, and auditable enterprise remediation workflow.

== Workshop Agenda

=== Part 1: SRE or DevOps practitioner

==== **Module 1:** From Infrastructure Complexity to Models-as-a-Service
Explore the resource allocation, duplicated model deployment, and cost governance challenges associated with traditional GPU infrastructure. Learn how Models-as-a-Service provides centralized model management, secure API access, shared resources, and a developer-friendly experience.

==== **Module 2:** System Administration with Agentic AI
Use the RHOAI Playground, Llama Stack, and MCP servers to inspect OpenShift resources, interact with collaboration services, and experience how Agentic AI can assist with system administration.

==== **Module 3:** Usage Analytics and Reporting
Use Grafana dashboards to observe model consumption, platform activity, and resource utilization. Understand the operational status, cost, and governance requirements of enterprise AI services.

==== **Module 4:** Install and Validate RHEL MCP
Establish a secure connection between RHOAI and distributed RHEL or Edge environments. Deploy and register the RHEL MCP Server so authorized AI clients can access approved remote system information and application data.

=== Part 2: Developer

==== **Module 5:** Build an AI-Assisted Development Environment
Open an OpenShift Dev Spaces workspace, install Cline, and connect a Cline-powered AI Development Agent to the RHOAI Models-as-a-Service endpoint.

==== **Module 6:** Try It Yourself
Build a simple application with AI assistance. Practice generating, reviewing, testing, and improving code while becoming familiar with the AI Development Agent workflow.

==== **Module 7:** Analyze Edge Application Logs
Use the AI Development Agent and RHEL MCP to securely retrieve application logs from distributed Edge environments. Analyze errors and operational risks, identify the root cause, and propose an appropriate remediation for the affected Edge application.

==== **Module 8 — Challenge / Bonus:** Remediate and Redeploy
Apply everything you have learned in an optional advanced challenge. Use the AI Development Agent to generate code or manifest changes, review and test the proposed remediation, and commit the approved changes to GitHub. Complete the workflow by using Argo CD, Ansible Automation Platform, and RHEL image mode to deploy and validate the update on the target RHEL or Edge environment.

[IMPORTANT]
====
Module 8 is an optional challenge and bonus exercise. Complete it if time permits or if you would like to explore the full end-to-end enterprise remediation workflow.
====

== Workshop Environment
This workshop runs on a shared OpenShift cluster. Each participant receives an individual user account and an OpenShift Dev Spaces development environment.

The foundation model and selected platform services are shared across participants. Development activities, RHEL targets, and remediation workflows are isolated and controlled according to the Lab environment.
