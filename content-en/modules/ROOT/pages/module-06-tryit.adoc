= Try It Yourself

Now that Cline is connected to the shared model, you will use it to complete a
small manufacturing application. The goal is not to generate a large project.
Instead, you will practice a controlled AI-assisted development loop:

. Inspect the starter code.
. Give Cline a focused task.
. Review the proposed change.
. Run the program.
. Ask for one small correction only if needed.

The exercise uses a single Python file and the Python standard library. This
keeps the task reliable for the shared `qwen3-4b-instruct` model.

== The Scenario

A production line records temperature, vibration, and defect count for each
manufactured item. Your application must read the sample CSV data and classify
each item as `PASS` or `REJECT`.

An item passes only when all of these rules are true:

* Temperature is between `18.0` and `25.0` degrees Celsius, inclusive.
* Vibration is no more than `4.0` millimeters per second.
* Defect count is no more than `2`.

The application must also print the total number of items, passed items,
rejected items, and the rejection rate.

== Open the Starter Project

The `code-for-fun` repository is already cloned into your Dev Spaces workspace
as `/projects/exercises`.

In the Explorer, open:

[source,text]
----
manufacturing-quality-checker/
├── starter/
│   ├── quality_checker.py
│   └── sample_readings.csv
└── solution/
    └── quality_checker.py
----

Open `starter/quality_checker.py` and read the existing code before asking
Cline to make changes. Notice that most of the application is already
implemented. There are only two `TODO` sections.

IMPORTANT: Do not open or copy `solution/quality_checker.py` yet. The
`starter` directory is your working area. The `solution` directory is an
instructor reference for comparison after you attempt the exercise.

== Complete the TODOs with Cline

Open the Cline panel and paste the following prompt:

[source,text,role=execute]
----
Open starter/quality_checker.py and starter/sample_readings.csv. Complete only
the code marked TODO 1 and TODO 2 in starter/quality_checker.py.

Requirements:
- Modify only starter/quality_checker.py.
- Do not change existing code outside the two TODO sections.
- Use only the Python standard library.
- Do not add dependencies or create new files.
- A reading passes when temperature is 18.0-25.0 C inclusive, vibration is
  at most 4.0 mm/s, and defect_count is at most 2.
- For rejected readings, list every failed rule as a short reason.
- The summary must show total, passed, rejected, and rejection rate.
- Keep the program simple and under 120 lines.
- After editing, summarize the changes in no more than five bullets.
----

When Cline proposes an action:

. Confirm that it is editing only `starter/quality_checker.py`.
. Review the changes around `evaluate_reading()` and `print_summary()`.
. Click *Save* to accept the proposed file edit if it follows the requirements.
. Do not approve package installation or unrelated files.

The *Save* button in Cline accepts the proposed change and writes it into the
starter file. If Cline updates the two TODO sections in separate steps, review
each proposed edit and click *Save* for each one.

image::cline-quality-checker-diff.png[Cline proposing changes to starter/quality_checker.py with the Save button visible,width=90%]

After both TODO sections are complete, Cline should show that all requested
tasks have been completed. Review the final diff one more time before moving
on to the terminal test.

image::cline-quality-checker-complete.png[Cline showing all tasks completed and the final TODO changes,width=90%]

[TIP]
====
Small, specific prompts usually work better than broad requests such as
“make this application enterprise-grade.” They also use fewer shared model
tokens and make the proposed code easier to review.
====

== Run the Quality Checker

Open a terminal in Dev Spaces:

. From the top menu, click *Terminal*.
. Click *New Terminal*.
. Wait for the terminal prompt to appear at the bottom of the editor.

image::devspaces-new-terminal.png[Open a new terminal from the Dev Spaces Terminal menu,width=90%]

If you prefer keyboard shortcuts, use kbd:[Ctrl+Shift+`] on Windows/Linux or
kbd:[Control+Shift+`] on macOS.

Then run:

[source,console,role=execute]
----
cd /projects/exercises/manufacturing-quality-checker
python3 starter/quality_checker.py
----

Your output should end with this summary:

[source,text]
----
Total: 8, Passed: 3, Rejected: 5, Rejection Rate: 62.5%
----

Also verify these boundary cases:

* `MFG-1007` must pass because its values are inside all limits.
* `MFG-1006` must show all three failed quality rules.
* A rejected item must not be counted as passed.

image::quality-checker-success-output.png[Successful quality checker output in the Dev Spaces terminal,width=90%]

== Debug with a Focused Follow-up

If the command fails or the totals are incorrect, do not ask Cline to rewrite
the entire program. Copy the error or describe the single failed check:

[source,text,role=execute]
----
The program output does not match the expected summary.
Inspect starter/quality_checker.py, identify the smallest correction, and edit
only the TODO function that is incorrect. Do not change other files, create
files, or install packages.
----

Run the program again after reviewing and approving the correction.

== Optional: Ask for an Explanation

If you finish early, ask Cline one read-only question:

[source,text,role=execute]
----
Explain evaluate_reading() in five short bullets. Do not edit any files.
----

This demonstrates that an AI development agent can help with both code changes
and code understanding.
